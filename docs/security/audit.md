# LearnSpace security audit

**Date:** 2026-11-16  
**Branch:** `feat/research-mode`  
**Scope:** repository source and the local Docker Compose development stack only. No production or third-party systems were tested. 

## Method and scan results

The Codex Security CLI was installed outside the repository in a scratch directory (v0.10.0). Its dry-run preflight completed, but authentication was not verified. The first standard scan stopped because the bundled Codex executable could not be resolved. After retrying with the installed optional binary, the standard scan and the deep scan both stopped before analysis: Bubblewrap could not create a namespace because unprivileged user namespaces are restricted in this environment. The raw outputs are in `docs/security/scans/codex-security-standard.log`, `codex-security-standard-retry.log`, and `codex-security-deep.log`. **No Codex Security scan completed and no scanner findings are claimed.**

`pnpm audit --prod` completed after the PDF.js update with `No known vulnerabilities found`; its output is saved at `docs/security/scans/pnpm-audit-after.txt`.

The manual review covered API route authentication and ownership checks, auth/session and redirect handling, database role and RLS policies, paper ingestion and parsing limits, prompt/data fencing and cache scope, link and rich-text rendering, the runner sandbox, error handling, rate limits, dependency and secret patterns, Dockerfiles, Compose port exposure, and debug/public endpoints. Browser checks used the local app and two local users only.

## Manual review notes

- **Authentication and authorization:** Reviewed the `apps/web/app/api/**` route tree and the shared session/ownership guards. Auth challenges, login, registration, verification, session read, logout, health, and OAuth endpoints are intentionally public or token/state guarded; protected app routes use session checks. `/api/v1/discovery/debug` requires a completed session. Login, registration, password recovery, and verification-resend paths have throttling. Session cookies are HTTP-only and SameSite=Lax; secure cookies are enabled in production. Local OAuth callback state is checked, and redirect destinations are constrained to local app/onboarding paths.
- **IDOR and RLS:** Created a second local account through the local registration API. Requesting the first user's study-session notes with the second user's session returned 404; direct navigation did not reveal the private note marker. The test account and inserted note data were removed. Source review covered ownership checks for papers, notebooks, tutor threads, coding attempts, research follows, and library resources; this browser IDOR probe was not repeated for every resource type. The live database roles `learnspace_app`, `auth`, `migrator`, `readonly`, `runner`, `worker`, and `ai` were not superusers and did not have `BYPASSRLS`. Reviewed user ownership policies, the active app role, and migration 0048's worker delete scope.
- **PDF ingestion and supply chain:** PDF fetching is HTTPS-only and allow-lists `arxiv.org` and `export.arxiv.org`; redirects are manually revalidated, credentials and custom ports are rejected, content type and PDF magic are checked, downloads are capped at 40 MiB, and fetches time out after 30 seconds. The parser path has a 30 MiB input limit, a 300-page limit, and a 30-second child timeout; the worker container has a 1 GiB memory limit. `vendor/pdf-inspector-researchpapers/PROVENANCE.md` records pinned upstream SHA `6845225193200a7779e69b2021e15fb1293b0adc`, no local patches, and the MIT license. No zip-bomb-like, deeply nested, or huge-page malicious PDFs were generated for this audit. The parser child has no separate per-process memory cap.
- **AI, retrieval, and citations:** Reviewed `fence()` use for learner notes, paper text, transcripts, and retrieved content; tutor cache eligibility and scope; and the Exa-only research/reference paths. Tutor answer caching is restricted to public-resource first turns and version/scope keys, and cached entries omit user goals/open questions. Paper/reference URLs are restricted to HTTPS or the allow-listed PDF hosts where applicable. No untrusted HTML rendering path was found: React text is escaped, KaTeX trust defaults remain off, diagrams use structured data, and PDF link annotations are limited to HTTP(S). No arbitrary agent tools are selected from retrieved content.
- **Sandbox:** The runner starts fresh learner containers with networking disabled, a read-only root, a 128 MiB `/tmp`, PID/CPU/memory limits, dropped capabilities, `no-new-privileges`, and learner processes running as `nobody`. Hidden tests remain in the runner/database, outside the learner work directory. The runner itself mounts `/var/run/docker.sock`; compromise of that internal service could control the host Docker daemon. The socket is not published as a host port, and the token is now random and required, but the runner remains a host-trusted component. This is not a production isolation boundary; production needs a separate Docker host or a different sandbox architecture.
- **Frontend, API behavior, and browser probes:** Source review found React-escaped text, no raw Markdown HTML plugin, constrained note/source links, generic API errors, and no password/session-token fields in the checked session response. A throwaway Playwright run using two local accounts verified anonymous API 401s and app redirect, cross-user study-note denial, safe rendering of `<img onerror>` input, rejection of `javascript:`/`data:` note links, logout invalidation, no stale data on mode switch, microphone access only after user action, and no CSP console violations. The committed e2e spec additionally checks Compose loopback defaults, unauthenticated paths/APIs, and response headers. No explicit CSRF token or Origin-validation layer was found; JSON-only mutation requests and SameSite=Lax cookies mitigate conventional cross-site form submission, but a hostile-origin mutation test was not run.
- **Secrets and infrastructure:** Secret-pattern checks found no credential in tracked `HEAD`. One history-search candidate was a false positive inside a GitHub source link in `docs/benchmarks/research-retrieval/fixtures/provider-responses.json`; no credential value was identified. The root `.env` is ignored by Git and has mode `600`; its values were not validated or copied into this report. Dockerfile review found the production web and backend images drop to `node`; the runner needs Docker daemon access for its current sibling-container design.

## Remaining risks and limits

- Codex Security standard and deep analysis could not run because the sandbox cannot create an unprivileged namespace in this environment; no authenticated scan result is available.
- The runner's Docker socket mount remains a high-impact host boundary if the runner itself is compromised. The shared runner token is now random and required, but that does not make a compromised runner safe. Keep this stack local; production needs an isolated Docker host or a different sandbox architecture.
- CSP is intentionally partial: it does not define `script-src`, because the current Next.js pages rely on inline scripts. HSTS is configured only for production and was not verified against a production deployment.
- Parser memory behavior against adversarial PDFs was not stress-tested. The container memory limit bounds the worker, but an input could still exhaust that worker's allowance.
- The full web typecheck passes after the PDF.js port; no full production build or full test suite was run as part of this audit. No tests targeted production or external services.
- During runtime Compose verification, the resolved environment was rendered in a tool output. The report and saved artifacts contain no credential values. If values supplied by the ignored `.env` are live, rotate them.
